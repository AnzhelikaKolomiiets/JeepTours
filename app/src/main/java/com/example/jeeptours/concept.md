# concept.md — JeepTours (Карпати)

## 1. Опис проекту (Project Overview)

### 1.1 Візія та місія
**JeepTours** — це персональна розумна система та сервіс on-demand бронювання, розроблена у вигляді нативного мобільного додатка, яка допомагає туристам легко та безпечно знаходити, обирати та замовляти джип-тури Карпатами.
**Місія проекту** — перетворити хаотичний ринок гірських екскурсій на впорядковану, живу та безпечну екосистему взаємин між водіями-гідами та туристами за допомогою автоматичного підбору маршрутів та системних підказок.

### 1.2 Проблема
* **Хаотичність та забудькуватість:** Туристи часто не знають контексту гірських маршрутів, їхньої складності, погодних ризиків та необхідного екіпірування.
* **Відсутність регулярності та гарантій:** Важко підібрати перевірений джип із високим рівнем безпеки (наявність лебідки, каркасу) та прозорою ціною.
* **Неефективний вибір:** Оголошення накопичуються без структури, відгуків та розуміння відповідності вимогам туристичної групи.

### 1.3 Рішення
Мобільний додаток, який забезпечує регулярний трекінг та бронювання гірських поїздок, структурує каталог джипів і маршрутів, нагадує про підготовку до туру та надає інтелектуальні підказки (AI) щодо того, як краще спланувати поїздку залежно від погодних умов і складу групи.

## 2. Опис платформи та архітектури (Platform & Stack)

### 2.1 Платформа
* **v1.0 – v1.x (Курсовий MVP):** Android Native Application, offline-first (локальне зберігання даних про заброньовані тури та карти для забезпечення максимальної автономності в горах).
* **v2.0+ (Post-MVP):** Додавання бекенду (Node.js / Go / Python) для хмарної синхронізації, замовлень у реальному часі, додатка для водіїв та складніших AI-обчислень.

### 2.2 Пропонований стек (Android)
Kotlin · Jetpack Compose (Material Design 3) · Clean Architecture + MVVM / MVI · Room Persistence Library · Dagger Hilt · Kotlin Coroutines & Flow · WorkManager (періодичні нагадування про поїздку, фоновий аналіз погоди).

---

## 3. Базовий функціонал (Core Features)

### 3.1 Управління турами та джипами
Картка авто (базові дані, клас джипа, місткість, наявність лебідки/каркасу); візуальна оцінка складності та тривалості маршруту.

### 3.2 Трекінг та бронювання
Журнал замовлень (обрані дати, деталі комунікації з водієм); розумні нагадування про час виїзду та чек-лист речей.

### 3.3 Інтелектуальний шар (AI)
* **AI Route Assistant:** Інтелектуальний підбір туру на основі побажань (екстрим, сімейний відпочинок, фото-тур).
* **Weather & Safety Insights:** Підказки щодо змін погоди та безпеки на високогір'ї.
* **Summary Generator:** Перетворення сирих запитів користувача на готовий чек-лист підготовки та Action Items.

## 4. Вимоги та специфікація (Requirements & Specs)

### 4.1 Функціональні вимоги (Functional Requirements)
* Система повинна дозволяти користувачу обирати клас джипа (Standard 4x4, Extreme Monster, VIP Comfort).
* Система повинна відображати деталізовану картку туристичного маршруту із позначенням висоти, складності та контрольних точок.
* Система повинна розраховувати підсумкову вартість поїздки на основі кількості пасажирів, обраного авто та додаткових опцій.
* Система (AI-модуль) повинна генерувати індивідуальні рекомендації щодо туру та екіпірування за введеними текстовими параметрами.

### 4.2 Нефункціональні вимоги (Non-Functional Requirements)
* **Performance:** Час відгуку інтерфейсу при навігації — до 100 мс; рендеринг карти — до 2 секунд.
* **Security:** Локальні персональні дані та історії бронювань шифруються за допомогою EncryptedDataStore.
* **Offline Behaviour:** Усі заброньовані тури, телефон водія та збережена карта доступні без наявності підключення до Інтернету.
* **Accessibility:** Підтримка адаптивної контрастної теми для читабельності екрана при яскравому сонці в горах.

### 4.3 Acceptance Criteria (Given / When / Then)
### 4.4 Граничні випадки (Edge Cases)
* **Повна відсутність зв'язку в горах:** Додаток автоматично перемикається в автономний оффлайн-режим та демонструє збережені дані поїздки.
* **Штормове попередження (погода):** AI-система блокує вибір складних високогірних маршрутів (наприклад, Піп Іван) та пропонує безпечні нішеві альтернативи.
* **Перевищення місткості джипа:** Якщо кількість людей більша за 6 осіб, система пропонує сформувати джип-конвой (2 авто).

### 4.5 Пріоритезація функціоналу (MoSCoW Matrix)
* **Must Have (MVP):** Каталог джипів та маршрутів, розрахунок вартості, створення та локальне збереження бронювання, Room DB.
* **Should Have:** AI Route Assistant, оффлайн-карта з чекпоінтами, нагадування від WorkManager.
* **Could Have:** Чат із водієм у реальному часі, підтримка Bluetooth-сенсорів геопозиції.
* **Won't Have (v1.0):** Онлайн-еквайринг (оплата карткою), додаток для водіїв (JeepTours Driver).

## 5. Етапи реалізації (Roadmap Focus)

* **Фаза 1 (MVP, Offline Tracker):** Картка авто, каталог маршрутів, локальне фіксування бронювання, Room DB.
* **Фаза 2 (AI Integration):** LLM (Gemini API) — генератор ідей для відпочинку, резюмування деталей туру та оффлайн-підказки.
* **Фаза 3 (Sync & Ecosystem):** Бекенд для диспетчеризації водіїв, синхронізація з Календарем Android та геолокаційними сервісами.

## 6. Системна архітектура (Clean Architecture)

### 6.1 Шари додатка
* **Presentation Layer:** Jetpack Compose + MVVM / MVI для інтерактивного UI.
* **Domain Layer:** Незалежна бізнес-логіка з Use Cases (наприклад, `CalculateTourPriceUseCase`, `GenerateAIRouteRecommendationUseCase`).
* **Data Layer:** Offline-first на базі Room Database, Encrypted DataStore та WorkManager для фонових задач.
* **AI Engine:** Гібридний шар — on-device LLM (Gemini Nano) для швидких задач у горах без зв'язку + Cloud AI API для складного аналізу маршрутів.
* **Backend & Sync Layer (Phase 3):** Бекенд для end-to-end шифрування (E2EE) та синхронізації замовлень.
